# 데이터 출처와 수집 방식

## 청약홈 (탭 2)

### 원본

모든 청약 데이터의 원본은 **한국부동산원 청약홈**이다.
- 화면: https://www.applyhome.co.kr/ai/aia/selectAPTLttotPblancListView.do
- 공공데이터포털 API: [분양정보 조회](https://www.data.go.kr/data/15101046/openapi.do), [경쟁률 조회](https://www.data.go.kr/data/15098905/openapi.do)

### 지금 쓰는 경로

청약홈 화면은 NetFunnel(대기열 시스템)이 걸려 있어 스크립트로 직접 긁기 어렵다.
그래서 같은 공공데이터포털 API를 받아 **서버사이드 렌더링으로 정리해 두는 `cheongyak.today`(오늘청약)** 를 파싱한다.
하루 4회 갱신되고, 아래 3개 페이지만 있으면 필요한 게 전부 나온다.

| 페이지 | 얻는 것 |
|---|---|
| `/calendar/YYYY-MM` | 그 달 공고 전체의 공고번호 + 접수일 |
| `/notices` | 접수중·접수예정 공고 목록 |
| `/notice/{공고번호}` | 지역·주소·시공사·총세대·주택형별 분양가/세대수·주택형별 1순위 경쟁률 |

### 나중에 바꿀 수 있는 것

3자 사이트에 의존하는 게 부담스러우면 **공공데이터포털 API 키를 발급받아 직접 호출**하면 된다.
무료이고 신청 즉시 발급된다. 이 경우 `scripts/apply_source.py` 의 `parse_notice()` 만 API 호출로 갈아끼우면 되고,
`fetch_apply.py` 이후 단계는 그대로 쓴다.

### 필터 규칙

- **주택구분**: 일반분양·공공분양만. 무순위·임의공급(줍줍)은 제외.
- **최소 세대수**: 30세대. 1~20세대짜리 잔여세대 공고가 목록을 잡아먹기 때문.
- **주요평형**: 총 세대수가 가장 많은 주택형. 그 단지의 주력 상품이다.
- **평균 경쟁률**: `1순위 총 접수건수 ÷ 일반공급 총 세대수`.
  (검증: 쌍용 더 플래티넘 서대문 1,112건 ÷ 28세대 = 39.71:1 — 언론 보도치와 일치)
- **마감/미달 판정**: 청약홈은 **접수가 0인 주택형의 경쟁률 행을 아예 내려주지 않는다.**
  따라서 경쟁률 표가 아니라 *일반공급이 있는 전체 주택형*을 기준으로 판정한다.
  경쟁률 행이 없는 주택형 = 1순위 미달.

## 뉴스 (탭 1)

| 매체 | 섹션 URL | 강점 | 본문 추출 |
|---|---|---|---|
| 한국경제 | `hankyung.com/realestate` | 정책·시장 | 가능 |
| 매일경제 | `mk.co.kr/news/realestate/` | 정책·시장 | **차단됨.** 제목만 참고 |
| 연합뉴스 | `yna.co.kr/economy/real-estate` | 정책·공공 | 가능 |
| 네이버(서울) | `land.naver.com/news/region.naver?city_no=1100000000` | **구 단위 개발** | 가능 |
| 네이버(경기) | `…city_no=4100000000` | 시 단위 개발 | 가능 |
| 네이버(인천) | `…city_no=2800000000` | 시 단위 개발 | 가능 |

네이버 지역뉴스는 나머지 셋이 다루지 않는 것을 잡는다 — 역세권 복합개발,
지구단위계획 결정, 추진위 승인 같은 구·시 단위 소식이다.
(예: 「방배동 서울레미콘 부지에 지식산업센터」, 「의정부 호원권역3구역 추진위 승인」)

목록 수집은 자동(`scripts/fetch_news.py`), **5건 선별과 요약은 Claude가 판단**한다.
이 부분은 자동화하지 않는다 — 무엇이 중요한지가 이 앱의 핵심이기 때문이다.

### 수집 단계에서 미리 거르는 것

| 거르는 것 | 판별 방법 |
|---|---|
| **광고성 분양단지 기사** | 모델하우스·견본주택·"분양 나선다"·"주목받는" 등. 단 전국·통계·경쟁률 같은 시장 표현이 있으면 살린다 |
| **회사 홍보·인사** | 게시판·부고·인사·수상·대표 선임 |
| **최근 4일 안에 고른 사안** | `data/news_history.json` 의 제목과 낱말 겹침 34% 이상 |
| **같은 날 중복 보도** | 후보들끼리 낱말 겹침 34% 이상이면 먼저 온 것만 남김 |

겹침 판정은 **낱말 단위**로 한다. 글자 2개씩 자르는 방식은
「장위15구역 3316가구 재탄생」과 「상도15구역 3204가구 재탄생」을 같은 기사로 잘못 묶는다.
흔한 말(구역·가구·재개발·서울…)은 빼고 비교하므로 지역·단지명이 다르면 갈린다.

걸러낸 것은 버리지 않고 `excluded` 에 사유와 함께 남긴다. 판단이 틀렸을 수 있어서다.

## 좌표 (앱 지도용)

주소를 좌표로 바꿔 `brief.json` 에 넣는다. 앱은 그 좌표로 지도를 그린다.

| 순서 | 출처 | 정확도 | 키 |
|---|---|---|---|
| 1 | 카카오 로컬 API (`dapi.kakao.com/v2/local/search`) | **지번까지** | `.env` 의 `KAKAO_REST_API_KEY` |
| 2 | OpenStreetMap Nominatim | 동 단위 | 없음 |

카카오 키는 **PC 의 `.env` 에만** 둔다. `.gitignore` 에 있어 GitHub 에 올라가지 않고,
APK 에도 들어가지 않는다. (marketability 프로젝트가 인프라 조회에 쓰는 키와 같은 것)

키가 없으면 자동으로 OSM 으로 내려간다. 동 단위라도 "어느 동네인가" 는 보인다.

주소 형태가 `…번지 일원`, `…지구 내 B-1BL` 처럼 지도에 없는 표현이라
번지 → 동 → 시군구 순으로 완화하며 찾는다. 한 번 찾은 주소는
`data/geocache.json` 에 남겨 다시 조회하지 않는다.

**현재 성적** — 17건 중 15건, 전부 지번 정확도.
못 찾는 2건은 신규 택지지구 블록 주소(광주 첨단3지구 A6블록, 검암역세권 B-1BL)로
지도에 아직 등록되지 않은 곳이다.
